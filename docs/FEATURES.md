# Three extensions — implementation specs

## 1. Phrase capture and Standard MIDI File export

**Goal:** keep a useful passage from an otherwise ephemeral sequence and bring it into a DAW.

- Record actual scheduled audible notes, including velocity, duration, swing and channel. Capture is independent of the 16-step trace.
- Record starts only during playback, stops with transport, and is capped at two minutes / 4,096 notes. Rest events are excluded. Pending notes beyond Stop are excluded; ringing notes are trimmed at the take boundary.
- Export type-0 SMF, 960 ticks per quarter, a tempo event, 4/4 meter, RPN ±2-semitone bend range, pitch bends and paired note-on/off events.
- Use the tempo at capture start as the file tempo. Convert actual elapsed milliseconds to ticks against that tempo, preserving performed timing even if tempo changes during the take (flattened tempo map).
- Microtonal export keeps fractional pitches with channel pitch bend; EDO playback is monophonic. A receiver must honor ±2-semitone bend sensitivity.
- Empty takes cannot export. Record replaces the previous take; Export does not clear it. Takes are session-only; JSON saves configuration, not recordings.
- Validation: decode generated bytes independently, check SMF headers, delta times, end-of-track, matching notes, rests, duration truncation and fractional pitch bends.

## 2. Euclidean rhythm gate

**Goal:** give evolving melodies a repeatable rhythmic skeleton.

- Optional gate, 2–32 steps, 0–steps pulses, and rotation 0–steps-1.
- Use the modular bucket distribution: pulse at step i when `(i * pulses) % steps < pulses`, then rotate right.
- Steps remain sixteenth notes. Markov history advances on every step, including rests; probability/density are applied independently. The mask is an AND gate on density.
- Zero pulses means silence; pulses equal steps means every step. Changes apply after already scheduled events, without a transport reset.
- Render the mask, label hits and rests accessibly, show current gate position. Persist/export with the project, default disabled for existing v1 patches.
- Validation: pulse counts for all parameter combinations, boundary cases, rotation, gap distances differing by at most one, deterministic scheduling with gate on/off.

## 3. Patch undo and redo

**Goal:** explore probabilities without losing a useful patch.

- Keep up to 60 prior project snapshots, excluding runtime playback status and history. Undo/redo restore notes, matrices, presets and generator rules.
- Group a continuous slider/number edit for 400 ms when it targets the same kind of edit. Distinct changes remain independent.
- New edits clear redo. Ignore tempo measurements from external MIDI/Link; restoring history preserves the current external clock BPM and sync routing.
- Toolbar buttons and Ctrl/Cmd+Z / Ctrl/Cmd+Shift+Z (Ctrl+Y also supported). Text/number inputs retain native text undo.
- Structural restores stop playback before changing state count; clear matrix selection to a valid index.
- History is session-only. No persisted undo stack.
- Validation: bounded history, grouping, branching after undo, redo ordering and no-op edits.
